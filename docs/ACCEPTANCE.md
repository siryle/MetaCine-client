# iPhone 客户端验收

## 验证环境

- iOS 17 或更高版本的 iPhone / iPhone 模拟器。
- 可连通的 MetaCine 实例及有效登录凭据。
- 服务器已保存资源频道及对应 Telegram 授权、115 账号、整理和入库配置。
- TMDB 片库和趋势需要服务端保存 TMDB 凭据；流媒体榜单需要配置 RE0，其他榜单依赖对应数据源连通性。

## 构建发布

1. 将 main 同步至 GitHub，确认 Actions 的模拟器测试和真机构建均成功。
2. 向任意分支（含 `main`）push，确认测试和构建成功后自动生成 `v<版本>-build.<运行编号>` 预发布 Release，包含 IPA 与 SHA-256；Actions artifact 同时保留。下载后使用 `shasum -a 256 -c *.sha256` 校验。
3. 从 Gitea 推送版本标签，确认镜像后 GitHub Release 包含相同版本 IPA。
4. 确认构建未要求 Apple ID、证书或描述文件。IPA 内部包含 `Payload/MetaCine.app`。
5. 使用自己的签名工具重新签名并安装，确认图标和启动页正常。
6. 连续 push 两次，旧构建不得因新 push 自动取消；两次成功构建应各自生成 Release，标签提交与说明中的 SHA 必须对应本次构建。同一次运行重试复用对应 Release，不得改写指向其他提交的标签。
7. PR、测试失败或构建失败时不得发布 Release；手动运行仍按「Publish the selected commit to a GitHub Release」选项决定是否发布。版本标签推送仍生成对应正式 / 预发布 Release。
8. iOS 工作流结束后应触发独立清理：iOS 构建记录只保留运行编号最新的 3 次已完成记录，旧记录及 artifacts / 日志一并删除，运行中和排队记录继续执行。失败记录也计入 3 次上限。
9. 带 IPA 的已发布 Release 只保留发布时间最新的 3 个，正式版和预发布版共同计数；旧 Release 与全部附件一并删除。草稿和其他 Release 保留。手动执行清理应使用相同规则，查询失败不得使用不完整列表删除数据。

## 服务器

1. 添加账号密码连接及令牌连接，分别测试正确凭据、错误凭据、错误地址、不可达端口和超时。
2. 测试 HTTP 内网 IP、HTTPS 域名和反向代理子路径。HTTPS 证书错误应显示系统网络错误。
3. 在 iOS 弹窗中允许本地网络权限；拒绝时显示失败，并可在系统设置中恢复后重新连接。
4. 编辑服务器，重启 App，确认服务器信息保留，账号密码由钥匙串恢复。
5. 添加两个具有不同数据的服务。切换后不得残留原服务器的榜单、搜索、订阅、历史或海报。
6. 在搜索或加载海报过程中切换、删除当前服务器，迟到响应不得覆盖新连接。
7. 断开连接后其他页面应提示连接；删除连接仅移除本机配置，不修改远端服务。
8. 修改服务端语言、图片、超时及代理，确认保存采用 PATCH，只修改页面显示字段。留空凭据和代理地址保留原配置。

## 榜单与订阅

1. 默认「热门」按后台一致顺序展示 IMDb 最热门电影、IMDb 最热门剧集、TMDB 趋势、AniList 热门和 Bangumi 今日动漫，分榜单横向滚动。核对猫眼、豆瓣和腾讯视频的全部分类与后台榜单推荐一致。猫眼应包含电视剧、网络剧、综艺、网络电影及电影票房，票房请求使用 `category=movie_playing`，无需 RE0 / TMDB 凭据及流媒体地区参数。
2. 切换 Netflix、HBO、Apple TV+、Disney+、Crunchyroll、Amazon Prime、Amazon 和 Hulu，检查电影 / 剧集 Top 10 及美国、韩国、英国、德国地区。Amazon Prime 和 Amazon 不提供韩国，切换时自动恢复受支持地区；切换平台重置为全部榜单。
3. 快速切换平台、分类和地区并下拉刷新，旧请求不得混入当前榜单。全部榜单最多并发四个，单个失败单独显示错误，其余继续加载；重试与下拉刷新传入 `refresh=1`，缓存回退显示提示。
4. 海报需要携带登录会话，优先使用后台榜单的 `image_url` / `poster`，TMDB、豆瓣、IMDb、AniList、Bangumi、猫眼及腾讯图片均走对应后端代理。多榜单出现相同海报时合并请求；返回页面、再次切换榜单、重新连接及重启 App 应复用本地图片缓存，不重复请求已缓存图片。不同服务器或账号不得混用缓存。TMDB 列表图片使用 `w342`，快速滚动和解码大图不应明显卡顿。
5. 查看作品简介、导演和主演；无资料时保留可理解的占位。库存与订阅状态 API 失败不能阻止榜单显示，失败的卡片不应展示订阅按钮，重试或下一次自动复核后恢复。
6. 豆瓣、AniList、Bangumi、IMDb、猫眼和腾讯作品订阅不能将原生 ID 当作 TMDB ID，同来源不同作品不应丢失或合并。详情尝试服务端唯一 TMDB 匹配，失败保留原资料；年份、类型、名称和有效海报应正确预填。第三方海报通过 catalog 代理，豆瓣及 TMDB 使用各自代理，均携带服务器会话。
7. 编辑名称或类型，确认旧 TMDB ID、原名和海报已清除。电影订阅保存时季数为 0。
8. 输入空标题、过长中文标题、非法年份、间隔小于 30 或大于 10080，应显示明确校验错误。
9. 新增、编辑、暂停、恢复、删除、单个检查、全部检查及筛选应正确显示结果。暂停订阅不参与全部检查。订阅页新增与编辑应推入原生页面，不出现弹窗；支持导航栏返回和侧滑返回，返回后保留列表筛选。保存成功自动返回并刷新列表，失败保留编辑内容；保存中不可重复提交或返回。
10. 同名重复订阅、服务器繁忙等错误显示服务端说明；已启动任务不因删除订阅而取消。
11. 订阅页在前台每 15 秒刷新，切至后台不继续轮询。
12. 发现页海报不显示序号；有效评分仅在左上角显示数字，不显示星形图标。右上角按「已订阅 > 已入库 > 订阅」展示单一状态，不再显示「有资源」或调用 `/api/resources/availability`。核对库存使用最近一次成功同步的完整快照，未同步或快照失效时不展示「已入库」。
13. 点击海报右上角「订阅」，应直接保存默认订阅，不打开详情或编辑表单；请求中显示「订阅中」并阻止重复点击，失败显示服务端说明且可重试。豆瓣先读取详情并尝试唯一 TMDB 匹配，匹配失败保留补全的名称与年份；最多并行三个并逐项更新，定期复核和快捷订阅复用本页补全身份。
14. 已有订阅（含暂停或指定季）显示右上角「已订阅」，优先于「已入库」，两者均不可点击。核对豆瓣 / TMDB、同名不同年份及不同作品类型，状态以统一接口返回值为准；冲突 TMDB ID 不回退匹配，豆瓣 ID 不可用于匹配 TMDB ID。当前列表约每 10 秒复核，后台及其他 Tab 不继续轮询。
15. 详情页「一键订阅」直接保存，「订阅设置」打开偏好表单。从详情页、搜索或订阅页新增、编辑和删除后，返回发现页状态应同步；一键订阅后订阅页也应更新。重新进入发现页、回到前台及下拉刷新可刷新服务端订阅状态。
16. 在后台 RE0 账号设置中将默认积分上限设为 3，再分别从发现页、片库、详情和资源结果一键订阅，核对创建请求 `source=all`、`auto_unlock=true`、`max_points=3`。设置表单应默认显示 3，可自定义或恢复账号默认值；读取配置失败需提示重试，不可静默使用 0 保存。
17. 分别测试全部来源、仅 RE0、仅 Telegram、仅 HDHaven 和仅 jying。RE0 和 HDHaven 专属订阅缺少 TMDB ID 应提示校验错误；Telegram、HDHaven 和 jying 不应依赖 RE0 配置。将服务端 HDHaven 账号默认上限设为 6，新增 HDHaven 订阅应读取 `/api/hdhaven/unlock/config` 并显示、保存 6；调整服务端上限后再次新增或点击恢复默认值应读取最新设置，不能固定为 0 或沿用 RE0 上限。接口失败或返回非法积分时应提示重试，不可静默保存；jying 支持不填 TMDB ID，不显示积分设置。全部来源依次检查 Telegram、RE0、HDHaven 和 jying。开启自动解锁时，服务器可处理上限内的付费资源，超过上限不解锁；上限为 0 或关闭自动解锁仅处理免费或已解锁资源。
18. 创建上限 3 的订阅后，将账号默认值改为 5，再编辑、暂停及恢复原订阅，其来源、自动解锁开关和上限 3 应保持不变。旧版无来源订阅维持 Telegram，禁止自动升级为付费解锁。
19. 对缺少海报或原图失败的流媒体 / 原生榜单，检查后端 TMDB 详情 / 唯一匹配补全封面。猫眼 HTTP、无协议、`w.h` 尺寸占位或带裁剪参数的官方图片地址应转换为代理支持的 HTTPS 地址；猫眼缺图匹配成功后，重启 App 不应重新匹配或下载相同封面。同名候选不唯一或后台图片接口不可用时保留固定占位，重试按钮仍可使用；快速切榜单及切服务器不应出现旧海报。

## 搜索与历史

1. 搜索 Tab 只显示片名输入框和搜索提示，不展示默认热门作品，也不提供类型、分类、地区、年份或排序筛选。提交片名后统一展示电影和电视剧结果，支持分页加载和下拉刷新搜索结果。
2. 无结果、频道部分失败、未授权和搜索超时应正确呈现；失败后可以重试。
3. 确认 115 提取码、磁力及电驴链接在查看原文、复制和分享后完整保留。
4. 搜索结果「一键订阅」应直接保存，带入类型、作品身份和已知季数；长按进入「订阅设置」。转存 / 下载需确认，并展示返回的任务详情。
5. 重复转存打开已有任务，不自动创建重复下载。
6. 查看历史全部 / 运行中 / 已完成 / 异常，搜索名称或消息，并核对进度和时间。
7. 展开文件明细，核对来源、目标、状态、大小和错误。运行中的任务详情每 4 秒刷新。
8. 对整理预览及订阅转存任务中服务端仍允许处理的未移动文件使用「校正匹配」；可搜索 TMDB 或手动输入 ID，电视剧支持第 0 季特别篇。保存仅更新服务端预览，不会移动文件；返回后核对新目标路径，逐项选择并二次确认执行。对结束的资源整理任务，只允许校正仍未移动且处于可匹配状态的条目；运行中、已移动和不可匹配条目不得操作。执行请求只发送所选文件，不会重新转存分享。
9. 停止任务后等待服务端状态更新；已完成文件不回滚。删除记录不影响媒体文件；运行中任务不能从列表删除。
10. 检查空列表、长作品名称、大字号、浅色 / 深色、横竖屏和小屏 iPhone 布局。
11. 搜索「名称:」等前缀、括号年份、S01E02 和「蓝光1080P」标题，检查卡片显示清理后的片名、左侧海报与右侧资源信息。TMDB 未配置、候选不唯一或海报失败时保留占位，原文、复制、分享、追更及转存仍可用。
12. 核对同名不同年份、已知 TMDB ID、原名匹配以及频道误标电影 / 电视剧的海报。连续搜索、刷新和切换服务器时，旧海报响应不能覆盖新结果；同一作品不同资源应复用资料查询。
13. 卡片底部操作区常规宽度下保持一行；窄屏或大字号时自动换为两行。「转存」与「下载」根据资源类型显示，按钮宽度随内容，不再占满卡片。匹配后的追更应预填作品名称、年份、海报与已知季数。
14. 输入关键词后，分别点击空白、结果卡片、频道标题和操作按钮，应收起键盘且按钮仍正常执行；再次点击输入框应正常聚焦、编辑和移动光标。键盘搜索键、页面搜索按钮和键盘工具栏「完成」均应收起键盘，拖动列表也可交互式收起。
15. 未提交片名时不发送片库搜索或推荐请求；清空片名会取消旧搜索并清除结果。搜索请求仅携带片名、电影或电视剧类型、页码及刷新标记，不发送分类、地区、年份或排序。无结果、TMDB 未配置、超时和缓存回退均有明确反馈，加载更多失败可重试且保留已有作品。
16. 片库海报保留评分，库存与订阅状态及一键订阅与发现页一致。发现页和搜索页点击作品海报或标题应推入原生作品详情，不出现弹窗；详情「搜索资源」继续推入原生资源搜索页，带入当前片名和作品身份。各层支持系统返回按钮和侧滑返回，不显示用于关闭弹窗的「完成」按钮；资源搜索的键盘工具栏仍保留「完成」。逐层返回后保留作品详情、原榜单和片库关键词、已加载分页及滚动位置，不清空或重新请求已有搜索结果。
17. 连续提交不同片名、清空搜索、分页期间刷新及切换服务器时，旧响应不得覆盖新结果。电影和电视剧各自保留结果顺序，同一数字 ID 的不同作品类型不能合并，已经结束的类型不再继续翻页。
18. 详情「搜索资源」并发查询 RE0、Telegram、HDHaven 和 jying，分别显示加载、计数、错误和结果。模拟一个来源失败或缓慢时，其他来源可正常展示和操作；来源标签按「全部、RE0、TG、栖影、聚影」排列，五项等宽填满内容区，不横向滚动，计数置于标签下方。检查窄屏、大字号、横竖屏和长计数时仍保持等宽，所选项有高亮及辅助功能选中状态；切换来源不重复请求。
19. 从已匹配详情搜索时，RE0、HDHaven 和 jying 请求包含 TMDB ID、类型、年份及季数，Telegram 只发送关键词；未匹配的猫眼等原生作品也应向 RE0 发送片名与已有提示，让服务端匹配。返回结果应排除不匹配的 ID、类型、电影年份及季数。修改查询片名后不再携带原作品身份。
20. 未解锁 RE0 和 HDHaven 资源应显示积分和「获取链接」。付费操作前确认积分，上限为已知消耗；积分未知或非法且尚未解锁时不发送解锁请求。已解锁资源允许重新获取链接。解锁接口错误只提示，不自动重试扣费。
21. RE0 和 HDHaven 获取链接成功后显示「转存」或「下载」，不会自动创建任务；需再次确认才提交。未获取链接时复制 / 分享资源页，获取后复制 / 分享完整链接及提取码；解锁前后卡片身份和展开状态不变，不同来源的相同 slug 不应合并。
22. jying 聚合直链应可直接复制、分享及转存；站内资源显示「获取链接」，经确认后仅调用 `/api/jying/resources/access`，不传付费参数，不自动转存。无访问权限时不请求链接，提示在站内核对；获取前后卡片身份不变。检查部分聚合来源失败时提示保留且其他结果可操作。
23. 读取、编辑、暂停和恢复 HDHaven、jying 订阅后，来源不得变成 Telegram；HDHaven 积分上限和付费许可不得被 RE0 默认值覆盖。订阅列表中 HDHaven 显示自身积分设置，全部来源显示 API 积分设置，jying 不显示积分。
## 支持范围

客户端覆盖榜单、资源搜索、订阅、任务历史及基础服务器管理。Telegram 首次授权、频道缓存扫描、HDHaven 绑定与签到、jying 登录、115 登录、通知渠道、STRM 路径映射、Emby 工具和复杂整理规则仍在 MetaCine Web 界面配置。客户端不运行本地下载器，不播放视频，也不在 iOS 后台承担服务器的定时任务。
